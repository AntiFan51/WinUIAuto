# 使用指南

[返回项目首页](../README.md)

## 1. 准备测试环境

按首页启动管理平台和 Agent，确认元宝已登录、Windows 桌面未锁定、Agent 与客户端权限级别一致。准备所需页面、账号和数据状态。

## 2. 录制操作

1. 在 Agent 中点击“开始录制”，随后正常操作元宝。
2. 需要验证结果时，按住 `Ctrl` 悬停确认高亮目标，再使用 `Ctrl + 右键` 添加验证点；备用入口为 `Ctrl + Shift + A`。
3. 需要等待或条件控制时，将鼠标悬停在目标上并按 `Ctrl + Shift + W`。
4. 完成操作后停止录制，在管理平台查看用例与证据。

普通编辑框以输入前后的值生成语义输入；聊天输入结合用户消息差分。文本或定位存在歧义时需人工复核，不能将未确认的步骤直接视为正确记录。

验证入口支持内容出现、消失、包含文本和关键词命中。普通右键作为测试动作录制，`Ctrl + 右键` 用于添加验证点。

## 3. 复核用例

平台支持搜索、重命名和删除用例，以及新增、编辑、删除和排序步骤。检查以下内容：

- 目标控件、输入文本与操作顺序是否符合测试意图。
- 断言是否对应操作后的业务结果，等待时间是否合理。
- IF/ELSE 的判断范围和分支步骤数是否正确。
- 是否存在待复核项、过时定位或依赖特定会话的数据。

`raw-trace.json` 保留原始事实；人工修改写入 `review-trace.json` 并生成 `cache-case.json`。删除用例会移入本地回收目录。IF/ELSE 使用扁平步骤及分支计数，不支持嵌套分支。

## 4. 原生回放

确认用例前置状态后，在管理平台点击“执行回放”，检查逐步状态、定位结果、断言和最终报告。可按用例需要选择回放前重启元宝。

回放期间不要操作鼠标、键盘或锁屏。原生回放验证的是当前 Cache Case 在当前客户端环境下的执行结果，不代表生成的 QTA 脚本已通过验证。

## 5. 生成与导出 QTA

完成 [AI 配置](CONFIGURATION.md) 后，进入 `Generated QTA` 页面生成代码。检查 warnings、步骤覆盖、定位和条件语义，再点击“导出到 QTA 仓库”。

导出位置为 `qta_runtime/qta_cases/windows_generated/`。同名且内容不同的文件使用递增文件名，避免覆盖。修改 Cache Case 后，旧代码可能标记为 `stale`，应重新回放、生成并验证。

生成脚本继承 `YBWindowsQtaBase`，使用 `Locator`、`Target` 和 `YBWindowsKit`。`platform/skills/` 是生成器读取的运行规则，不能从工程中删除。

## 6. 执行 QTA

安装首页列出的 Python 依赖后，在项目根目录执行以下命令。将文件名替换为实际导出的脚本：

```powershell
cd .\qta_runtime
.\.venv\Scripts\python.exe .\qta_cases\windows_generated\<case_name>.py
```

平台不会自动执行生成代码。运行前需人工审查，并确认客户端和账号处于预期状态。通过与否以 QTA 输出中的“测试用例最终结果”及失败步骤为准，不能仅依赖进程退出码。

## 7. 生成汇总

在项目根目录执行：

```powershell
npm run report -- 10
```

输出位于 `platform/runtime/reports/`，汇总最近指定数量的用例，最多 100 条。`not_run` 表示尚未原生回放，不计为成功；此报告不代表 Python QTA 实跑结果。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 页面打不开 | 确认 `npm start` 正在运行，使用终端输出的地址，不要双击 HTML 文件 |
| Agent 无法连接 | 确认平台已启动、两个进程端口一致，检查地址环境变量是否覆盖默认值 |
| C# 编译器未找到 | 安装带 MSBuild、Roslyn 和 .NET Framework 桌面组件的 Visual Studio / Build Tools；仅 .NET SDK 不足以满足现有脚本 |
| 首次启动没有用例 | 初始库为空，通过 Agent 录制后刷新平台 |
| AI 未配置或生成失败 | 检查实际服务地址、密钥、模型 ID、API 协议及网络权限；查看平台错误与本地诊断 |
| 回放定位失败 | 检查客户端版本、页面前置状态、权限、桌面会话及用例中的动态内容 |

故障排查时不要将真实密钥、完整录制内容或敏感截图粘贴到公开问题记录中。
